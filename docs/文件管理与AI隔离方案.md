# 文件管理与 AI 隔离方案

日期：2026-11-05。状态：方案，未实施。

本方案改变三件事：项目数据的存放位置、交接文件的流向、AI 工具对原件的可达性。它推翻 README 中“项目数据不写入材料工作目录”的约定，见第 9 节。

## 1. 现状与问题

当前路线：材料文件夹 → `%LOCALAPPDATA%\Mask\projects\<路径哈希>\` → 浏览器下载到 `Downloads` → 用户自行交给 Codex → 粘贴回还原页 → 再下载到 `Downloads`。

| 编号 | 问题 |
| --- | --- |
| 1 | 没有告诉用户该在哪个目录运行 Codex；在材料文件夹运行时 AI 能直接读原件 |
| 2 | 真名版还原结果和 `mapping.json` 都下载到 `Downloads`，与脱敏稿放在一起 |
| 3 | 下载文件名统一为 `材料1.脱敏.md`，跨项目、跨批次混淆；移除材料后编号顺延，同一编号前后指不同文件 |
| 4 | 项目目录按路径哈希藏在 `%LOCALAPPDATA%`，界面没有入口；离开完成页后历史导出找不回 |
| 5 | 每次导出新建 uuid 目录，移除材料不删快照，还原结果只增不减 |
| 6 | 项目与材料文件夹的路径绑定，移动或改名后变成新的空项目 |
| 7 | 材料列表静默跳过 `.doc` 等不支持的文件 |
| 8 | 还原结果只有时间戳，不记录来自哪份 AI 结果、对应哪次导出 |

## 2. 原则

三类数据，三个位置，按能否外发区分：

| 类别 | 位置 | 能否外发 |
| --- | --- | --- |
| 原件、映射、快照、真名版 | 案件文件夹内，`AI` 账户无权限 | 不能 |
| 代号稿、AI 结果 | 案件文件夹内的 `脱敏\`，`AI` 账户唯一可读写的位置 | 能，整个文件夹就是交接单位 |
| 浏览器下载 | 取消 | — |

映射与原件同样敏感：拿到原件就不需要映射。因此两者放在一起，不单独加密。

## 3. 文件系统

```
D:\案件\张三合同纠纷\            ← 项目 = 这个文件夹
├─ 原件\                        用户的文件，Mask 只读
│   ├─ 游泳培训协议.docx
│   └─ 采购合同.pdf
├─ 脱敏\                        代号稿，AI 在这里工作
│   ├─ AGENTS.md                代号规则 + “结果写到 结果\”
│   ├─ 用AI账户启动.cmd          见第 6 节
│   ├─ 材料1.脱敏.md             每次导出就地覆盖
│   ├─ 材料2.脱敏.md
│   └─ 结果\                    AI 产出放这里，还原页自动列出
├─ 还原结果\                    真名版，与结果文件同名
├─ AGENTS.md                    一句话：只在 脱敏\ 工作，不读 原件\
└─ .mask\                       项目数据
    ├─ project.json             核对结果、代号映射、材料编号、还原记录
    ├─ mapping.json             官方 {代号: [原文]}，每次保存同步
    ├─ 快照\材料1.docx …         导入时的原件副本，移除材料时一起删
    └─ process.lock、session.url
```

规则：

- 材料只认 `原件\` 里的第一层文件。首次打开根目录有松散文件的文件夹时，提示一次“把这 N 个文件移入 原件\”；同一磁盘内移动不改内容。不同意则不做。
- 从别处拖入的文件复制到 `原件\`，使案件文件夹自包含。
- 材料编号在导入时分配，移除后不复用。界面显示“材料 1 · 游泳培训协议.docx”；`脱敏\` 内只用中性名。
- `脱敏\` 中 `材料*.脱敏.*`、`AGENTS.md`、`用AI账户启动.cmd` 由 Mask 维护，导出时覆盖同名文件并删除已移除材料的旧稿。`结果\` 和其他文件不动。
- 取消 ZIP、取消 `/api/download`、取消“导出映射文件”。`mapping.json` 常备于 `.mask\`，可直接用于 `has.sh text restore --mapping`。还原页“改用映射文件”的入口保留，用于 `.mask\` 丢失或跨项目还原。
- `%LOCALAPPDATA%\Mask\` 只保留 `recent.json`（项目路径列表）和 `llama.log`。首次打开某文件夹时，若旧位置有该路径哈希的项目，一次性搬入 `.mask\`。旧的 `.roundN` 目录不迁移，由用户手动删除。
- 不支持的文件（`.doc` 等）在材料列表中灰显并写明原因。

## 4. 项目页

启动后先到项目页，不再直接进入某个文件夹：

- 最近项目列表：名称、路径、材料数、待确认数、最近打开时间，数据直接读各项目的 `project.json`。
- 点一行进入该项目；左上角面包屑显示项目名，点击回项目页，切换不重启进程。
- “打开文件夹…”调用系统文件夹选择框（服务端用 tkinter，浏览器无法选目录）。选到无 `.mask\` 的文件夹即新建项目。
- 路径不存在的项目灰显，提供“重新定位”和“从列表移除”；移除只删记录。
- `--workspace` 参数变为可选：给了就直接打开该项目并写入最近列表。`启动工作台.cmd` 不带参数。
- 一个进程同一时刻只有一个当前项目；`process.lock` 继续保证同一项目不被两个窗口同时修改。`Recognizer` 改为进程级共用，切换项目不重启 llama-server。

## 5. 流程

1. 打开项目，选材料，识别，核对。与现在相同。
2. 导出：写入 `脱敏\`。完成页只显示路径、“打开文件夹”、“启动 AI”三样，没有下载链接。
3. AI 在 `脱敏\` 工作。`AGENTS.md` 说明代号规则并要求输出写到 `结果\`。
4. 还原页顶部列出 `结果\` 下的 `.md`/`.txt`，新文件标“待还原”，点击载入；聊天文字仍可粘贴。
5. 保存：写到 `还原结果\<结果文件同名>.md`，`project.json` 记录结果文件、还原时间和对应的导出批次。
6. 案件结束：`⋯ → 清理交接文件夹` 删除 `脱敏\`（含 `结果\`）。`还原结果\` 和 `.mask\` 由用户处置。

## 6. AI 隔离

目标是 AI 工具“不能读”原件，而不是“请不要读”。同一 Windows 账户下的程序对文件权限完全相同，所以 AI 必须以另一个账户运行，由 NTFS 权限隔离。

| 频率 | 内容 | 谁做 |
| --- | --- | --- |
| 每台电脑一次 | 建本地标准用户 `AI`；登录一次，安装 Codex 并登录 | 用户 |
| 每台电脑一次 | 在 Mask 设置页输入 `AI` 账户密码，存入 Windows 凭据管理器 | 用户 |
| 每个项目 | 设置文件夹权限、生成启动脚本 | Mask 自动 |
| 每次启动 AI | 点“启动 AI” | 用户一键 |

权限（Mask 用 `icacls` 设置，文件夹所有者可以改自己文件的 ACL，不需要管理员）：

| 位置 | `AI` 账户 |
| --- | --- |
| 案件根目录 | 仅列出，不继承到子目录 |
| `原件\`、`.mask\`、`还原结果\` | 无权限；去掉继承，只保留当前用户 |
| `脱敏\` | 读写 |

- 创建项目时设置 `原件\`、`.mask\`、`还原结果\`；导出时授予 `脱敏\`。打开项目时检查一次，复制到另一块盘后权限会重置为继承，不对则重新设置。
- “启动 AI”：Mask 用凭据管理器里的密码调用 `CreateProcessWithLogonW`（`runas` 背后的接口，普通用户可用），以 `AI` 身份在 `脱敏\` 打开终端并运行 Codex。没有保存凭据时退回到 `用AI账户启动.cmd`，它用 `runas /user:AI`，每次要输密码。
- `AI` 账户不能是管理员。
- `AI` 账户里的 Codex 独立安装、独立登录，升级或换账号要在该账户里再做一次。

其他能做到硬隔离的方式，作为替代而不是叠加：Docker 容器只挂载 `脱敏\`；云端 AI 只上传 `脱敏\`。

不算隔离、只作为第二层减少误操作的做法：`AGENTS.md`、AI 工具自身的 deny 规则和沙箱设置、隐藏或只读属性。

## 7. 加密

Mask 不做加密。原件、`project.json`、快照、还原结果在磁盘上都是明文。静态加密交给系统：

- 本机是 Windows 11 家庭版，没有 EFS，没有 BitLocker 管理界面。可用的是 设置 → 隐私和安全性 → 设备加密，前提是硬件有 TPM。没有该项时，只能升级专业版或使用第三方加密容器。
- 系统加密防硬盘丢失和其他账户，不防同一账户下的程序。对 AI 隔离没有作用，第 6 节才是。

## 8. 对应问题

| 问题 | 解决方式 |
| --- | --- |
| 1 | `脱敏\` 独立；`AI` 账户对原件无权限；两份 `AGENTS.md` |
| 2 | 取消下载；真名版写入 `还原结果\`；映射只在 `.mask\` |
| 3 | 编号固定不复用；界面显示编号与原文件名对应 |
| 4 | 三个文件夹可见；完成页“打开文件夹”；就地覆盖后没有历史批次 |
| 5 | 导出覆盖；移除材料删快照；一个清理动作 |
| 6 | `.mask\` 随案件文件夹移动；项目页可重新定位 |
| 7 | 不支持的文件灰显并说明 |
| 8 | 还原文件与结果文件同名，`project.json` 记录来源 |

## 9. 需要拍板

1. 项目数据写入案件文件夹，推翻 README 的约定。文件夹不可写时报错，不做回退路径。
2. 材料必须在 `原件\` 子目录，首次打开时一次性提示移入。
3. AI 隔离采用本地 `AI` 账户方案。Docker 和云端作为文档中的替代说明，不实现。

## 10. 实施顺序

每阶段完成后可独立使用：

1. 文件系统布局、迁移、导出覆盖、`AGENTS.md`、结果列表、还原记录。改动集中在 `workflow.py`、`server.py`（删下载接口，加“打开文件夹”“列出结果”）、`live.js`（完成页、还原页）。
2. 项目页、`recent.json`、进程级 `Recognizer`、面包屑切换。
3. `AI` 账户：`icacls` 设置、凭据管理器、`CreateProcessWithLogonW` 启动、设置页。

## 11. 未核实

- Codex 对案件根目录 `AGENTS.md` 的读取依赖它的项目根识别规则，实现时确认；`脱敏\AGENTS.md` 在当前目录，一定会被读取。
- Codex 在 Windows 原生环境下的沙箱是否限制读取。本方案不依赖它。
- `icacls` 在案件文件夹位于网络盘或 exFAT 分区时不可用，这类位置不支持 NTFS 权限；实现时在创建项目处明确报错。
