# 网关方案

日期：2026-11-12。分支 `feature/gateway`。状态：网关本体和 DeepSeek Harness 的接入已实现并在本机接入（第 2 至 8 节，第 11 节第 1 至 4 步）；面板和记录页（第 9 节）已做在工作台里，桌面端外壳（9.6）未做；Codex 的接入已实现并在本机接入（6.5，Codex CLI 0.167.1）；Claude Code 未接。

把原来的 `guard proxy` 做成全机共用的网关：Agent 的模型地址指向它，它把请求里已确认的原文换成代号后转给 Agent 原来的上游，回复原样传回。参考了 [yetone/magpie](https://github.com/yetone/magpie)（`2cf09b1`，MIT）的网关、脱敏和 Agent 接入三部分；各节标出借鉴的文件。

第一版接 DeepSeek Harness（dsh），上游是 DeepSeek 官方接口。

沿用的既定做法（见 [架构与模式](架构与模式.md)）：网关不运行识别模型，只认映射库里已确认的原文和校验位有效的号码；回复不还原，真名只在工作台出现。

## 1. 与现有代理的差别

| | 原来的 `guard proxy` | 网关 |
| --- | --- | --- |
| 进程 | 每个案件文件夹起一个 | 全机一个 |
| 映射库 | 启动时由 `--workspace` 指定 | 每个请求按 Agent 的工作目录选 |
| 上游 | 启动时由 `--upstream` 指定 | 每个 Agent 一个 |
| 改写范围 | 请求体里每个字符串 | 只改正文，协议字段不碰 |
| 记录 | 无 | 每个请求一行，不含原文 |
| 接入 Agent | 手工改配置 | `install` / `uninstall`，只动自己写的那一块 |

`guard proxy` 及其命令行参数已由 `gateway` 取代并删除。`guard hook` 不变。

## 2. 模块

```
mask/
├─ payload.py        请求体的结构：哪些字符串是正文、工作目录写在哪（新）
├─ vault.py          替换函数拆出来，网关按映射库版本只编译一次（改）
├─ store.py          写文件遇到占用时重试（改）
└─ modes/
   ├─ gateway.py     网关：入口、选映射库、改写、转发、记录、后台启动（新）
   ├─ guard.py       只留 hook；create_proxy、run_proxy 已删除（改）
   └─ install.py     dsh 的接入加一项：网关地址（改）
integrations/guard/dsh/index.mjs   dsh 启动时带起网关（改）
```

命令：`python -m mask gateway`（前台运行）；`python -m mask gateway start`（后台启动，已在运行则不动）；`python -m mask install|uninstall dsh`。

## 3. 一条请求的处理

地址形如 `http://127.0.0.1:8788/<agent>/<原路径>`。前缀之后的路径和查询串原样拼到该 Agent 的上游地址后面。

1. **认 Agent。** 前缀不在 Agent 表里（`gateway.AGENTS`：`dsh → https://api.deepseek.com/anthropic`，`codex → https://chatgpt.com/backend-api/codex`），返回 404。带 `Upgrade: websocket` 的请求返回 426：Codex 每个会话先试 WebSocket，收到 426 后立刻改用普通请求（实测只试一次；网关不应答或应答别的状态时它重试 5 次，约 10 秒）。
2. **读请求体。** `Content-Encoding` 是 zstd 的先解压（Codex 的请求体是 zstd），转发时不再压缩；其他编码返回 415。有请求体但不是 JSON 对象，返回 400。没有请求体（GET，如 Codex 每次启动取模型列表）直接转发，不记录。
3. **读工作目录，选映射库。** 见第 4 节。
4. **改写。** 见第 5 节。
5. **强校验。** 正文里仍有校验位有效的身份证号、统一社会信用代码，返回 400，不转发（现有的 `STRICT`）。
6. **转发。** 请求头去掉 `Host`、`Content-Length`、`Content-Encoding`，其余原样带上，API Key 或登录凭据随之传给上游。Agent 没有写 `Accept-Encoding` 时网关写 `identity`：回复原样传回，上游按 httpx 默认值压缩的话 Agent 解不开（Codex 的模型列表实测如此）。
7. **回复。** 状态码、响应头、正文原样流回，不解析、不还原。客户端断开时关闭上游连接。
8. **记录。** 见第 7 节。

第 2 至第 5 步任何一处抛出异常都不转发，返回 503，异常写入 `gateway.log`。连不上上游返回 502。错误体是 Anthropic 的 `{"type":"error","error":{"type","message"}}`，对 Codex 也用这个形状：Codex 把 400 的响应体整段显示给用户，原因能读到，不重试。

dsh 上传图片走 `/v1/files`，请求体是 multipart，不是 JSON，按第 2 步被拒；dsh 的文档说明上传失败时改用内联 base64 重发整个请求。图片内容网关不检查。

请求体仍用 `json.loads` 解析、改完 `json.dumps` 写回，不移植 magpie 的字节级遍历器（`internal/redact/json.go` 的 `walk`）。

## 4. 工作目录与映射库

Agent 把自己的工作目录写在发给模型的请求里。`payload.py` 按 Agent 读出它，再用现有的 `project.find(cwd)` 找项目（子目录也算）。

| Agent | 写法 | 位置 |
| --- | --- | --- |
| DeepSeek Harness | `Current working directory: "<路径>".`，路径是 JSON 字符串写法（反斜杠成对） | “Current runtime context” 文字块 |
| Claude Code | `Primary working directory: <路径>`，行首可有 ` - ` | 系统提示或 `role: system` 的消息；中途换目录时在 `<system-reminder>` 里，带 ` (was …)` |
| Codex | `<cwd>路径</cwd>`，路径原样写 | 用户消息的 `<environment_context>`，`<cwd>` 是其中第一项 |
| OpenCode | `Working directory: <路径>` | `<env>` 块 |

后三行出自 `internal/gateway/workdir.go`；dsh 一行取自本机 dsh 0.2.2-rc.1 的会话记录，Codex 一行与本机 Codex 0.167.1 的请求一致。已实现 dsh 和 Codex 两行，各用各的写法：读系统提示和各条消息（Anthropic 的 `messages`、Responses 的 `input`）里的文字块，不读工具结果（里面是文件内容），有多处时取最后一处。其余在接入对应 Agent 时加。

三种结果：

| 情况 | 处理 |
| --- | --- |
| 读出工作目录，找到项目 | 用该项目的映射库改写，再做强校验 |
| 读出工作目录，没有项目 | 用全部项目的映射库改写，同一原文在多个项目里时取最近修改的项目的代号，再做强校验。在项目之外的目录里，请求仍可能引用用户输入或读到的原文 |
| 读不出工作目录 | 同上。见第 10 节第 1 项 |

映射库按文件修改时间缓存，工作台确认了新主体后下一个请求就生效。

**路径里的真名。** 回复不还原带来一个后果：模型只见过代号，它发出的工具调用里的路径也是代号写法。如果案件文件夹的路径本身含有已确认的原文（如 `D:\案件\张三合同纠纷`），工作目录会被改写成带代号的路径，模型按它读写文件必然失败。网关在第 3 步检查：工作目录的路径含映射库里的原文时返回 400，说明对应哪个代号（不写出原文，错误信息会留在 Agent 的会话里）。其他处理方式见第 10 节第 2 项。

## 5. 哪些字符串改写

对请求体里的每个字符串，按它所在的键和路径决定。规则按 `internal/redact/json.go`（`kept`、`isID`、`toolArgs`、`defKeys`、`sealed`）重写在 `payload.py`。下表是 magpie 覆盖的全部协议；已实现的是 Anthropic Messages 和 Codex 发的 OpenAI Responses 用到的部分：键名单全表；带签名的 `thinking` 块和带 `encrypted_content` 的 `reasoning` 项；`*tool_use` 的 `input`；顶层的 `tools`、`tool_choice`、`output_config`、`output_format`、`text`、`client_metadata`；`input` 里 `type` 为 `additional_tools` 的项的 `tools`（Codex 把工具定义放在这里，顶层没有 `tools`）。Responses 的 `function_call.arguments`、`custom_tool_call.input` 是字符串，按“其余字符串”改写，结果与“全部改写”相同。Chat Completions 的 `function.arguments` 等没有 Agent 在用，未加。

| 位置 | 处理 | 原因 |
| --- | --- | --- |
| 协议自己的键：`model`、`id`、`type`、`role`、`name`、`signature`、`encrypted_content`、`data`、`url`、`image_url`、`media_type`、`status`、`tool_use_id`、`call_id` 等，以及以 `_id`、`Id`、`_ids`、`Ids` 结尾的键 | 不改、不查 | 厂商按原样比对；改了返回 400 |
| 以 `data:` 开头的值 | 不改、不查 | 编码后的文件 |
| 带签名的块：`type` 为 `thinking` 或 `reasoning` 且有 `signature` / `encrypted_content`，或带 `thoughtSignature` | 整块不改、不查 | 厂商拿签名校验原文。里面是模型写的，模型没见过真名 |
| 工具调用的参数：`*tool_use` 的 `input`，`*_call` 的 `arguments` / `input`，`function.arguments` | 全部改写，上面的键名单在这里不适用 | 键是工具自己的，`name`、`url` 在这里是正文 |
| 请求顶层的定义：`tools`、`tool_choice`、`response_format`、`output_config`、`stream_options`、`client_metadata` 等 | 只改 `description` | 其余被厂商当结构读 |
| 其余字符串（系统提示、消息、工具结果） | 改写 | 正文 |

改写与 `vault.redact(text, escaped=True)` 相同：已知原文按长度从长到短替换成代号，同时匹配 JSON 转义后的写法，以及原文的 UTF-8 字节按 Windows 代码页读出的乱码（`vault.garbled`）。乱码按两种字节对齐各算一份：双字节代码页里原文的第一个字节可能和前一个字节配成一个字；最后一个字可能和后一个字节配对，不算在内，所以替换后最多留下原文的一个字节。解码用 Windows 自己的（Python 的 `mbcs`），Python 的 `gbk` 对未定义的字节对处理不同，与 PowerShell 的输出对不上。只在 Windows 上生效；不足两个字的乱码不算。强校验只查“改写”和“全部改写”两行里的字符串。

dsh 在请求顶层附带 `dsh_session_log`、`dsh_plugin_packages` 两个自己的字段，按“其余字符串”处理。

`guard.scrub` 现在供 hook 检查用户输入的一句话，保持不变。

## 6. 接入与断开

### 6.1 DeepSeek Harness（已实现，已在本机接入）

dsh 的 DeepSeek 官方路由（条目 `llm-deepseek`，插件 `@deepseek-ai/dsh-llm-deepseek-api-key`）走 Anthropic Messages 协议，地址的取值顺序是：条目里的 `baseURL`，环境变量 `DEEPSEEK_BASE_URL`，官方地址 `https://api.deepseek.com/anthropic`。API Key 用请求头 `x-api-key` 发送。依据是该插件的 README（dsh 0.2.2-rc.1）。

接入是在 `~/.dsh/cordis.patch.yml` 里 Mask 自己的标记块中多写一项，和拦截插件在同一块：

```yaml
# >>> mask guard
- insert:
    - id: mask-guard
      …
- id: llm-deepseek
  config:
    baseURL: "http://127.0.0.1:8788/dsh"
# <<< mask guard
```

- **为什么不用环境变量。** 试过把 `DEEPSEEK_BASE_URL` 写进 `~/.dsh/.env`：dsh 启动时拒绝并退出（`.env` 里不允许出现决定网络去向的变量，只能由启动它的环境设置）。写进 Windows 的用户环境变量会影响所有程序，且要重新登录才对已打开的程序生效。
- **patch 条目是整项替换**，不做深合并（`dsh-app-boot` README）。home 级 patch 的优先级高于各 profile 的。所以用户自己配过 `llm-deepseek`（在 home 级或任一 profile 的 patch 里，dsh 的模型设置页会写这一项）时，Mask 的这一项会把它整项盖掉。现在的做法是发现这种条目就拒绝接入并说明在哪个文件。接入之后用户再去 dsh 的模型设置里改 DeepSeek 路由的设置，改动不会生效。
- **是否已接入从文件现读**，不另存标志，没有 `gateway.json`。上游地址固定为官方地址，写在 `gateway.AGENTS`。
- **断开只删自己的那一块**（沿用原有的 `_patch`）。
- **顺序**：先启动网关并确认它在听，再写技能和 patch。
- **范围**：只有 `deepseek-official` 这条路由（API Key）经过网关。在 dsh 里选了别的提供方的模型时不经过；用 DeepSeek 账号登录的路由（`deepseek-account`）是另一个条目，不经过。面板要把范围写在该行的说明里。
- `install dsh` 和 `uninstall dsh` 仍是一个开关：技能、拦截插件、网关地址一起装、一起卸。
- magpie 是另加一个自己的 provider 并改默认模型，为此维护整套模型目录（`internal/agent/dsh.go`）；Mask 只改地址，没有移植那部分。

### 6.5 Codex（已实现，已在本机接入）

依据是本机 Codex CLI 0.167.1（ChatGPT 账号登录）的实测，2026-11-12。

- **地址。** `~/.codex/config.toml` 顶层的 `openai_base_url` 整个替换内置 OpenAI 通道的地址。ChatGPT 登录时原地址是 `https://chatgpt.com/backend-api/codex`，Codex 请求它下面的 `/responses`（POST，OpenAI Responses 协议，zstd）和 `/models`（GET）；登录凭据在请求头 `authorization`、`chatgpt-account-id` 里，原样转给上游。
- **接入是在文件最前面加一行**（顶层键必须在第一个表之前）：

  ```toml
  openai_base_url = "http://127.0.0.1:8788/codex"  # Mask 网关；mask uninstall codex 移除
  ```

  断开是删掉值为 Mask 地址的这一行。按字节读写，文件其余部分和换行符不变。是否已接入从文件现读。`install codex` 同时把技能写入 `~/.codex/skills/mask/`；没有装拦截 hook（Codex 的 hook 格式未核对）。
- **不接入的三种情况**，说明原因：文件里已有别的 `openai_base_url`（如 magpie 的）；`model_provider` 不是 `openai`（请求不走内置通道）；不是 ChatGPT 登录（API Key 登录的上游是 `api.openai.com/v1`，网关里 Codex 只有一个上游）。因此不需要 6.2 的 `gateway.json`。
- **本机接入后的验证（2026-11-13）。** 方法同 dsh：`codex exec`（CLI 0.167.1）经 WMI 在包外运行，用的是真实的 `%LOCALAPPDATA%\Mask` 和已接入的 `config.toml`；案件是虚构的借款备忘，项目 `83e729b1e26eced48944`。
  - 提问里已确认的姓名和公司：模型复述的是代号，记录里两个代号各 1 处，`project` 是项目目录名。
  - 读一份未导入、含已确认名字的备忘：Codex 用 PowerShell 读出原文，模型复述的是代号，记录里有对应代号。
  - 含校验位有效的身份证号的提问：400，Codex 显示“Mask 已拦截：请求含未脱敏的身份证号码”，记录 `refused: strict`。
  - 工作目录的路径含已确认的姓名：400，Codex 显示对应代号，记录 `refused: path`。
  - `$mask`（项目事先已交接）：模型加载技能，自己运行 `skill start` 和 `skill status`，只读 `mask-handoff/` 的脱敏稿作答，全程用代号，这次会话的本机会话文件里没有原文。`codex exec` 默认的 workspace-write 沙箱不允许 `skill start` 写 `%LOCALAPPDATA%\Mask`（Codex 如实报告失败，没有去读原件），这一项是加 `--sandbox danger-full-access` 跑通的，与 dsh 在“完全权限”下验证相同。
  - 停掉网关：`codex exec` 一直重连，120 秒没有结束，也没有给出明确原因。重新启动网关后恢复正常。
  - 用户在提问里写的原文、工具读到的原文，仍在 Codex 本机的会话文件（`~/.codex/sessions`）里，不发往模型。与 dsh 相同。
  - **发现并修掉一处漏网**：Codex 第一次用 `Get-Content` 不带编码读 UTF-8 文件，PowerShell 按 Windows 代码页（936）解码，输出是乱码；乱码里的姓名不是映射库里的写法，没有被替换，原样发给了模型（那条请求的记录 `tags` 为空）。这种乱码可以还原出原文。dsh 的工具结果走同一条路径，同样受影响。已修（见第 5 节末），2026-11-14 让 Codex 照同样方式读同一份备忘复验：乱码里的姓名和公司换成了代号，记录里各 1 处，会话文件里没有原文。
  - 没有做：Codex 桌面应用；还原页；等用户点“交给 AI”的等待。
- **没有带起网关的入口。** dsh 由拦截插件带起；Codex 没有对应的东西。重启电脑后网关没运行，Codex 发不出请求，面板显示“网关没有运行”和“启动”按钮。第 10 节第 3 项的登录自启未做。
- **验证。** 用 `-c openai_base_url=…` 把一次 `codex exec` 指到临时端口上的网关（改动后的代码）：提问里已确认的虚构姓名到模型时是代号，模型回复里是代号，记录的 `project` 是项目目录名（`<cwd>` 读对了）；含校验位有效的身份证号的提问返回 400，Codex 显示了原因；WebSocket 只试一次即退回；模型列表正常。接入和断开在临时的 `CODEX_HOME` 上经工作台面板走通，断开后 `config.toml` 与原来逐字节相同。2026-11-13 在本机真实接入（`install codex` 经 WMI 在包外运行），之后不带任何覆盖参数的 `codex exec` 正常应答，网关的 `/mask/health` 记到了这条请求。没有做：Codex 桌面应用；工具结果里的原文（那次会话里 Codex 的沙箱起不来，读文件的工具没跑成，由测试覆盖）；压缩会话（`/responses/compact`）的请求。

### 6.4 本机现状（2026-11-11 核对）

| Agent | 现在指向 | 第一版 |

magpie 再次运行并接管 dsh 时，默认模型会改成它的路由，请求不再经过 Mask，而 Mask 的 patch 块还在。magpie 的两个扩展点不能作为边界：请求钩子不能拒绝请求，抛错或超时即放行（`docs/subsystems/gateway-request-hooks.md`）；JS 中间件能拒绝，但限时 250 毫秒，失败同样放行（`docs/subsystems/gateway-middleware.md`）。

## 7. 记录

`%LOCALAPPDATA%\Mask\gateway\<日期>.jsonl`，一个请求一行，网关启动时删除 30 天前的文件：

```json
{"t": "2026-11-11T10:02:31", "agent": "dsh", "project": "3f2a…", "tags": {"<人名[1].人名.名称>": 3}, "ms": 4, "status": 200}
{"t": "2026-11-11T10:03:02", "agent": "dsh", "project": "3f2a…", "strict": ["身份证"], "refused": "strict", "status": 400}
```

`project` 是项目数据目录名（工作目录哈希），不是路径；`*` 表示读不出工作目录、用了全部项目；`null` 表示该目录没有项目。`ms` 是网关自己花的时间。`refused` 是没有发出的原因：`strict`、`path`、`not-json`、`encoding`、`error`。不记原文、不记请求文字、不记工作目录。借鉴 `internal/maskrec`：只记代号、类别和次数。

## 8. 网关的运行

- 只监听 `127.0.0.1:8788`，端口固定。被别的程序占用时启动失败并说明。
- 连上游时用用户的代理设置（环境变量或系统代理），由网关自己读取：dsh 带起网关时传来的 `NO_PROXY` 含 IPv6 项，httpx 自带的读取会因此报错。系统代理的例外名单只按上游的主机名匹配（`gateway.bypassed`）：`urllib.request.proxy_bypass` 还会对主机做反向 DNS 查询，本机每个上游耗时 16 秒，两个上游时网关启动超过 `gateway start` 等待的 30 秒；改后启动约 5 秒。
- `GET /mask/health` 的响应头带 `X-Mask: gateway`，用来判断在听的是不是 Mask 的网关；正文是每个 Agent 最近一条请求的时间（只在内存），面板用它区分“已写入，等 Agent 重启”和“生效中”。
- `gateway start` 在后台启动网关并等它开始监听，已在运行则直接返回。日志在 `%LOCALAPPDATA%\Mask\gateway\gateway.log`。
- **dsh 每次启动时带起网关**：拦截插件加载时运行 `gateway start`。重启电脑后不需要用户先开 Mask。
- **断开的顺序**：先改回 Agent 的配置。网关不随之停止：已打开的 Agent 窗口还在用旧设置，要等它重启。网关运行到本次登录结束。
- 网关没运行时，已接入的 Agent 连不上，请求发不出去。

## 9. 界面

原型：[prototype/mask-gateway.html](../prototype/mask-gateway.html)，双击打开，左下角“原型”切换外壳和场景。样式沿用工作台（`mask/web/app.css`）：底部抽屉、开关、朱色只用于待办。

### 9.1 面板

一份面板，两页：**Agent** 和 **记录**。它只读写全机状态（各 Agent 的配置、网关的记录文件），不依赖当前打开的案件。

入口不变：选材料页的“Agent”小药丸和核对页的 `⋯ → 接入 Agent`。药丸上的圆点：绿色为有 Agent 接入，朱色为需要处理（网关没运行、接入被改掉）。

Agent 页从上到下：

1. **网关状态，一行。** 三种：没有 Agent 接入时一句说明；运行中显示今天的请求数、替换处数、拦下条数；没运行时朱色，带“启动”按钮。
2. **Agent 列表，一个 Agent 一行**：名称、版本、状态、“详情”、开关。
3. 一句范围说明：开关对本机所有案件生效。

每行的状态：

| 状态 | 圆点 | 文字 | 右侧 |
| --- | --- | --- | --- |
| 未接入 | 无 | 未接入 · 直连 `<上游>` | 开关，关 |
| 接入中 | 蓝，闪 | 正在启动网关… / 正在写入配置… | 开关，禁用 |
| 已写入 | 蓝，闪 | 已接入 · 重启 `<Agent>` 后生效 | 开关，开 |
| 生效中 | 绿 | 已接入 · 生效中 | 开关，开 |
| 网关没运行 | 朱 | 已接入 · 网关没有运行，请求发不出去 | 开关，开 |
| 被改掉 | 朱 | 接入已被改掉 · 请求现在不经过 Mask | 开关，开 |
| 不能接入 | 无 | 原因一句，如“模型地址由 magpie 管理” | 文字“不能接入”，无开关 |
| 暂未支持 | 无 | 暂未支持 | 无 |

DeepSeek Harness 的开关是技能、拦截插件、网关地址三样一起。原型里这一行画的还是“不经网关”，以工作台里的实现为准。已实现的范围：9.1 至 9.3、9.5，面板打开时每 4 秒刷新一次状态。没有做的：9.4（dsh 没有“被改掉”的判断，那是 Claude Code 的情形）；被拦下的记录只给原因，没有“去处理”的按钮；记录只显示当天。“生效中”的判断是：网关收到过该 Agent 在配置写入之后发来的请求。

“详情”在该行下方展开，不换页：改动位置（文件和键）、请求去向（`Agent → Mask → 上游`）、接入前的值，以及三个动作：看改了什么、看它的记录、断开并还原。

### 9.2 打开开关

点一下就接入，不弹确认：

1. 状态依次显示“正在启动网关…”“正在写入配置…”，约一两秒。
2. 完成后该行自动展开详情，顶部提示“已接入 Claude Code，重启它后生效”，带“撤销”，6 秒内可点。撤销等于立即断开并还原。
3. Agent 重启后第一条请求到达网关，状态变为“生效中”，不需要用户回来操作。

不弹确认的理由：改动只有一行，接入前的值已存下，随时能原样还原；未接入的行展开“详情”可以先看将要改的内容。magpie 的开关也是直接生效。

### 9.3 断开并还原

关掉开关，或点详情里的“断开并还原”，抽屉内容换成确认页（不叠第二层弹窗，左上角可返回）：

- 标题：断开 `<Agent>` 和 Mask？
- 要改回的文件和行差异，删除的行朱色加删除线。
- 朱色提示：断开后它发给模型的内容不再经过 Mask，真名会原样发出；重启该 Agent 后生效。
- 按钮：取消 / 断开并还原。

对应 magpie 的“断开并还原”对话框。多出来的是那句后果提示。

### 9.4 接入被改掉

该行变朱色并自动展开，并排列出“Mask 写的”和“现在是”两个值，两个动作：重新接入；不接了，移除记录（不动 Agent 的文件）。

### 9.5 记录

分“按请求”和“按代号”。

- **按请求**：时间、Agent、案件、结果（换了 N 处 / 没有要换的 / 未发送）。点开一行看换了哪些代号各几处。被拦下的行是朱色，点开给出原因和去处理的按钮，如“含未脱敏的身份证号，没有发出”→“去工作台处理这份材料”。
- **按代号**：今天每个代号被换了多少处。原文不在这里显示，在工作台的“实体”面板看。

### 9.6 为桌面端留的位置

现在的外壳是浏览器里的工作台，面板放在底部抽屉里。以后做桌面端时：

- **同一份面板放进窗口**，成为顶部“案件 / Agent / 记录”里的两页。面板只通过本机服务的接口读写（`/api/hosts…`），不直接碰文件，换外壳不用改。
- **网关不随窗口关闭而停**。关窗口是收到托盘，网关继续运行。
- **托盘图标**带状态圆点，点开是精简面板：网关状态一行、各 Agent 的开关、“打开 Mask”“退出”。
- **退出时还有 Agent 接入**，询问：断开并退出（主按钮）/ 只退出（Agent 发不出请求，直到 Mask 再次启动）/ 取消。借鉴 `internal/gui/quitask.go`。
- 登录自启由桌面端负责（第 10 节第 3 项）。
- 黑色灵动岛只给核对工具用；窗口顶部的页面切换用浅色分段控件。

接口（工作台和以后的桌面端共用）：

| 接口 | 作用 |
| --- | --- |
| `GET /api/hosts` | 网关状态、今天的计数、每个 Agent 的状态和详情 |
| `PUT /api/hosts/{id}` | 接入或断开 |
| `GET /api/hosts/{id}/preview?enabled=` | 将要改的文件和行差异 |
| `POST /api/gateway/start` | 启动网关 |
| `GET /api/gateway/log?day=` | 记录 |

## 10. 待定

1. **读不出工作目录的请求。** Agent 会发不带环境信息的小请求（如给会话起标题），里面可能有用户输入的文字。已按建议实现：用全部项目的映射库改写，同一原文在多个项目里时取最近修改的那个项目的代号。这类请求的回复不需要还原。dsh 的标题请求是否带工作目录，要在 dsh 里真实接入后从记录里的 `project` 确认。
2. **案件文件夹路径含真名。** 现在拒绝并说明。其他做法：
   - 按项目明确开启“路径照发”：工作目录这一个字符串不改写，文件夹名会发给厂商。
   - 只在回复的工具调用参数里把带代号的路径换回真实路径：要解析流式回复，一段路径可能被切在两个事件之间，需移植 `internal/redact/writer.go` 的扣尾逻辑。
   - 用户把文件夹改成不含真名的名字。项目按路径哈希绑定，改名后是新的空项目（[文件管理与 AI 隔离方案](文件管理与AI隔离方案.md) 问题 6），要先解决这一点。
3. **随登录启动。** dsh 已由拦截插件在启动时带起网关，不需要登录自启。接 Claude Code 时它没有这样的入口，届时再定：建议接入时写 `HKCU\…\Run`，断开最后一个时删除（magpie 在 Windows 上也只有登录自启，`internal/autostart/autostart_windows.go`）。
4. **dsh 的图片。** 上传被拒后 dsh 改用内联 base64，网关不检查图片内容。是否要在已有项目的工作目录里直接拒绝带图片的请求。
