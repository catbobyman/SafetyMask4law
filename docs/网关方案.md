# 网关方案

日期：2026-11-11。状态：方案，未实施。分支 `feature/gateway`。

把现在的 `guard proxy` 做成全机共用的网关：Agent 的模型地址指向它，它把请求里已确认的原文换成代号后转给 Agent 原来的上游，回复原样传回。参考了 [yetone/magpie](https://github.com/yetone/magpie)（`2cf09b1`，MIT）的网关、脱敏和 Agent 接入三部分；各节标出借鉴的文件。

沿用的既定做法（见 [架构与模式](架构与模式.md)）：网关不运行识别模型，只认映射库里已确认的原文和校验位有效的号码；回复不还原，真名只在工作台出现。

## 1. 与现有代理的差别

| | 现在的 `guard proxy` | 网关 |
| --- | --- | --- |
| 进程 | 每个案件文件夹起一个 | 全机一个 |
| 映射库 | 启动时由 `--workspace` 指定 | 每个请求按 Agent 的工作目录选 |
| 上游 | 启动时由 `--upstream` 指定 | 每个 Agent 一个，接入时记下 |
| 改写范围 | 请求体里每个字符串 | 只改正文，协议字段不碰 |
| 压缩请求体 | 当作“不是 JSON”拒绝 | 解 zstd / gzip |
| 错误体 | 一律 Anthropic 形状 | 按入口协议 |
| 记录 | 无 | 每个请求一行，不含原文 |
| 接入 Agent | 手工改配置 | 开关，可预览、可还原 |

`guard proxy` 及其命令行参数由 `gateway` 取代并删除。`guard hook` 不变。

## 2. 模块

```
mask/
├─ payload.py        请求体的结构：哪些字符串是正文、工作目录写在哪（新）
├─ store.py          写文件加重试（改）
└─ modes/
   ├─ gateway.py     网关：入口、选映射库、改写、转发、记录（新）
   ├─ guard.py       只留 hook；create_proxy、run_proxy 删除（改）
   └─ install.py     Agent 表：dsh 之外加 claude 的接入、断开、预览（改）
```

命令：`python -m mask gateway [--port 8788]`；`python -m mask install|uninstall claude`。

## 3. 一条请求的处理

地址形如 `http://127.0.0.1:8788/<agent>/<原路径>`。前缀之后的路径和查询串原样拼到该 Agent 的上游地址后面。

1. **认 Agent。** 前缀不在 `gateway.json` 的 Agent 表里，返回 404。
2. **读请求体。** 按 `Content-Encoding` 解 zstd 或 gzip，其他编码返回 415。有请求体但不是 JSON 对象，返回 400。没有请求体（GET）直接转发。借鉴 `internal/gateway/request_bounds.go`。
3. **读工作目录，选映射库。** 见第 4 节。
4. **改写。** 见第 5 节。
5. **强校验。** 正文里仍有校验位有效的身份证号、统一社会信用代码，返回 400，不转发（现有的 `STRICT`）。
6. **转发。** 请求头去掉 `Host`、`Content-Length`、`Content-Encoding`，其余原样带上，登录凭据随之传给上游。请求体以未压缩的 JSON 发出。
7. **回复。** 状态码、响应头、正文原样流回，不解析、不还原。客户端断开时关闭上游连接。
8. **记录。** 见第 7 节。

第 2 至第 5 步任何一处抛出异常都不转发，返回 503。错误体按路径决定形状：路径以 `/messages` 或 `/messages/count_tokens` 结尾用 Anthropic 的 `{"type":"error","error":{"type","message"}}`，其余用 OpenAI 的 `{"error":{"message","type","code","param"}}`。连不上上游返回 502。借鉴 `writeErrorAs`（`internal/gateway/gateway.go`）。

请求体仍用 `json.loads` 解析、改完 `json.dumps` 写回，不移植 magpie 的字节级遍历器（`internal/redact/json.go` 的 `walk`）。

## 4. 工作目录与映射库

Agent 把自己的工作目录写在发给模型的请求里。`payload.py` 按 Agent 读出它，再用现有的 `project.find(cwd)` 找项目（子目录也算）。

| Agent | 写法 | 位置 |
| --- | --- | --- |
| Claude Code | `Primary working directory: <路径>`，行首可有 ` - ` | 系统提示或 `role: system` 的消息；中途换目录时在 `<system-reminder>` 里，带 ` (was …)` |
| Codex | `<cwd>路径</cwd>` | 用户消息的 `<environment_context>` |
| OpenCode | `Working directory: <路径>` | `<env>` 块 |

出处是 `internal/gateway/workdir.go`。只读调用方自己写的那一层（系统提示、系统消息、上表列出的包裹块），用户消息里引用的同样一行不算；有多处时取最后一处。第一版只实现 Claude Code 一行，其余在接入对应 Agent 时加。

三种结果：

| 情况 | 处理 |
| --- | --- |
| 读出工作目录，找到项目 | 用该项目的映射库改写，再做强校验 |
| 读出工作目录，没有项目 | 只做强校验。与现在的 hook 一致 |
| 读不出工作目录 | 待定，见第 10 节第 1 项 |

映射库按文件修改时间缓存，工作台确认了新主体后下一个请求就生效（沿用 `run_proxy` 的做法）。

**路径里的真名。** 回复不还原带来一个后果：模型只见过代号，它发出的工具调用里的路径也是代号写法。如果案件文件夹的路径本身含有已确认的原文（如 `D:\案件\张三合同纠纷`），工作目录会被改写成带代号的路径，模型按它读写文件必然失败。第一版在第 3 步检查：工作目录的路径含映射库里的原文时返回 400，说明是路径的哪一段、对应哪个代号。其他处理方式见第 10 节第 2 项。

## 5. 哪些字符串改写

对请求体里的每个字符串，按它所在的键和路径决定。四张表移植自 `internal/redact/json.go`（`kept`、`isID`、`toolArgs`、`defKeys`、`sealed`）。

| 位置 | 处理 | 原因 |
| --- | --- | --- |
| 协议自己的键：`model`、`id`、`type`、`role`、`name`、`signature`、`encrypted_content`、`data`、`url`、`image_url`、`media_type`、`status`、`tool_use_id`、`call_id` 等，以及以 `_id`、`Id`、`_ids`、`Ids` 结尾的键 | 不改、不查 | 厂商按原样比对；改了返回 400 |
| 以 `data:` 开头的值 | 不改、不查 | 编码后的文件 |
| 带签名的块：`type` 为 `thinking` 或 `reasoning` 且有 `signature` / `encrypted_content`，或带 `thoughtSignature` | 整块不改、不查 | 厂商拿签名校验原文。里面是模型写的，模型没见过真名 |
| 工具调用的参数：`*tool_use` 的 `input`，`*_call` 的 `arguments` / `input`，`function.arguments` | 全部改写，上面的键名单在这里不适用 | 键是工具自己的，`name`、`url` 在这里是正文 |
| 请求顶层的定义：`tools`、`tool_choice`、`response_format`、`output_config`、`stream_options`、`client_metadata` 等 | 只改 `description` | 其余被厂商当结构读 |
| 其余字符串（系统提示、消息、工具结果） | 改写 | 正文 |

改写就是现有的 `vault.redact(text, escaped=True)`：已知原文按长度从长到短替换成代号，同时匹配 JSON 转义后的写法。强校验只查“改写”和“全部改写”两行里的字符串。

`guard.scrub` 现在供 hook 检查用户输入的一句话，保持不变。

## 6. 接入与断开

状态文件 `%LOCALAPPDATA%\Mask\gateway.json`，不含原文和密钥，不加密：

```json
{"port": 8788,
 "agents": {"claude": {"upstream": "https://api.anthropic.com",
                       "was": {"env.ANTHROPIC_BASE_URL": null}}}}
```

`was` 是接入前的原值，`null` 表示原来没有这个键。原来有值时它同时是 `upstream`，没有时取厂商默认地址。做法出自 magpie 的 `stash.json`（`internal/agent/stash.go`）。

**Claude Code。** 接入是在 `~/.claude/settings.json` 的 `env` 里写 `ANTHROPIC_BASE_URL = http://127.0.0.1:<端口>/claude`。其他键不动，包括用户已有的 hooks。文件按 JSON 读入、改一个键、以两格缩进写回。

规则：

- **是否已接入从文件现读**：该键的值等于上面这个地址即已接入。不另存标志。
- **重复接入不改文件**，`was` 只在第一次接入时记。
- **断开只动自己的**：键的值仍是 Mask 写的地址才改回 `was`（`null` 即删除该键；`env` 因此变空且原来不存在时一并删除）。值已被改成别的，不动文件，只把该 Agent 从 `gateway.json` 移除并说明。借鉴 `Disconnect`（`internal/agent/applied.go`）。
- **预览**：接入和断开都是“旧文本 → 新文本”的函数。预览调用同一个函数，用 `difflib` 给出行差异。断开必须先看预览再确认；接入直接执行，可撤销，改动随时能看（第 9 节）。magpie 是把配置拷到临时目录跑真正的断开再比较（`internal/agent/preview.go`），目的相同。
- **写入**：同目录临时文件再改名。改名被拒绝（目标正被别的程序读）时重试，50 次、间隔 10 毫秒，出自 `internal/steady/steady.go`。`store.write` 用同一做法：网关在读 `vault.mask` 的瞬间工作台保存，现在的 `temp.replace(path)` 会失败。
- **被别的工具改掉**：magpie 等工具接管 Claude Code 时会覆盖同一个键，之后请求不再经过 Mask，Claude Code 照常工作。`gateway.json` 里有该 Agent 而文件里的值已不是 Mask 的地址时，面板和 `skill status` 标明“接入已被改掉”。

**DeepSeek Harness。** 现有的技能加拦截插件不变。

**本机现状**（2026-11-11 核对）：

| Agent | 现在指向 | 第一版 |
| --- | --- | --- |
| Claude Code | 直连，订阅登录 | 接入 |
| Codex | magpie：`openai_base_url = http://127.0.0.1:3425/backend-api/codex` | 不接 |
| DeepSeek Harness | magpie：`profiles/*/cordis.patch.yml` 的 `llm-pi-ai` | 不接，沿用拦截插件 |

后两个的地址项由 magpie 维护：它运行时每 30 秒重写 dsh 的路由（`KeepDshWired`，`internal/agent/dsh.go`），对 Codex 会判定为“被替换”并可改回（`Drift`、`Reapply`，`internal/agent/applied.go`）。magpie 的两个扩展点不能作为边界：请求钩子不能拒绝请求，抛错或超时即放行（`docs/subsystems/gateway-request-hooks.md`）；JS 中间件能拒绝，但限时 250 毫秒，失败同样放行（`docs/subsystems/gateway-middleware.md`）。

## 7. 记录

`%LOCALAPPDATA%\Mask\gateway\<日期>.jsonl`，一个请求一行，保留 30 天：

```json
{"t": "2026-11-11T10:02:31", "agent": "claude", "project": "3f2a…", "status": 200,
 "tags": {"<人名[1].人名.名称>": 3}, "strict": [], "ms": 4}
```

`project` 是项目数据目录名（工作目录哈希），不是路径。不记原文、不记请求文字、不记工作目录。被拒的请求记拒绝原因的类别。借鉴 `internal/maskrec`：只记代号、类别和次数。

## 8. 网关的运行

- 只监听 `127.0.0.1`。端口被占用时启动失败并说明。
- `GET /mask/health` 返回版本，供面板判断在运行的是不是 Mask 的网关。
- **接入的顺序**：先启动网关并用 `/mask/health` 确认它在听，再写 Agent 的配置。网关起不来就不写，Agent 不会指向没人听的端口。网关是后台进程，启动方式同 `skill start`。
- **断开的顺序**：先改回 Agent 的配置。最后一个 Agent 断开后网关不立即停：已打开的 Agent 窗口还在用旧设置，要等它重启。网关运行到本次登录结束。
- 网关没运行时，已接入的 Agent 连不上，请求发不出去。
- 网关记下每个 Agent 最近一条请求的时间（只在内存），面板用它区分“已写入，等 Agent 重启”和“生效中”。
- 是否随登录启动，待定，见第 10 节第 3 项。

## 9. 界面

原型：[prototype/mask-gateway.html](../prototype/mask-gateway.html)，双击打开，左下角“原型”切换外壳和场景。样式沿用 `mask.html`：底部抽屉、开关、朱色只用于待办。

### 9.1 面板

一份面板，两页：**Agent** 和 **记录**。它只读写全机状态（`gateway.json`、各 Agent 的配置、记录文件），不依赖当前打开的案件。

入口不变：选材料页的“Agent”小药丸和核对页的 `⋯ → 接入 Agent`。药丸上的圆点：绿色为有 Agent 接入，朱色为需要处理（网关没运行、接入被改掉）。

Agent 页从上到下：

1. **网关状态，一行。** 三种：没有 Agent 接入时一句说明；运行中显示今天的请求数、替换处数、拦下条数；没运行时朱色，带“启动”按钮。
2. **Agent 列表，一个 Agent 一行**：名称、版本、状态、“详情”、开关。
3. 一句范围说明：开关对本机所有案件生效。

每行的状态：

| 状态 | 圆点 | 文字 | 右侧 |
| --- | --- | --- | --- |
| 未接入 | 无 | 未接入 · 直连 `<上游>` | 开关，关 |
| 接入中 | 蓝，闪 | 正在启动网关… / 正在写入配置… | 开关，禁用 |
| 已写入 | 蓝，闪 | 已接入 · 重启 `<Agent>` 后生效 | 开关，开 |
| 生效中 | 绿 | 已接入 · 生效中 | 开关，开 |
| 网关没运行 | 朱 | 已接入 · 网关没有运行，请求发不出去 | 开关，开 |
| 被改掉 | 朱 | 接入已被改掉 · 请求现在不经过 Mask | 开关，开 |
| 不能接入 | 无 | 原因一句，如“模型地址由 magpie 管理” | 文字“不能接入”，无开关 |
| 暂未支持 | 无 | 暂未支持 | 无 |

DeepSeek Harness 的开关仍是现有含义（技能加拦截插件），状态写明“不经网关”，“原因”里说明为什么。

“详情”在该行下方展开，不换页：改动位置（文件和键）、请求去向（`Agent → Mask → 上游`）、接入前的值，以及三个动作：看改了什么、看它的记录、断开并还原。

### 9.2 打开开关

点一下就接入，不弹确认：

1. 状态依次显示“正在启动网关…”“正在写入配置…”，约一两秒。
2. 完成后该行自动展开详情，顶部提示“已接入 Claude Code，重启它后生效”，带“撤销”，6 秒内可点。撤销等于立即断开并还原。
3. Agent 重启后第一条请求到达网关，状态变为“生效中”，不需要用户回来操作。

不弹确认的理由：改动只有一行，接入前的值已存下，随时能原样还原；未接入的行展开“详情”可以先看将要改的内容。magpie 的开关也是直接生效。

### 9.3 断开并还原

关掉开关，或点详情里的“断开并还原”，抽屉内容换成确认页（不叠第二层弹窗，左上角可返回）：

- 标题：断开 `<Agent>` 和 Mask？
- 要改回的文件和行差异，删除的行朱色加删除线。
- 朱色提示：断开后它发给模型的内容不再经过 Mask，真名会原样发出；重启该 Agent 后生效。
- 按钮：取消 / 断开并还原。

对应 magpie 的“断开并还原”对话框。多出来的是那句后果提示。

### 9.4 接入被改掉

该行变朱色并自动展开，并排列出“Mask 写的”和“现在是”两个值，两个动作：重新接入；不接了，移除记录（不动 Agent 的文件）。

### 9.5 记录

分“按请求”和“按代号”。

- **按请求**：时间、Agent、案件、结果（换了 N 处 / 没有要换的 / 未发送）。点开一行看换了哪些代号各几处。被拦下的行是朱色，点开给出原因和去处理的按钮，如“含未脱敏的身份证号，没有发出”→“去工作台处理这份材料”。
- **按代号**：今天每个代号被换了多少处。原文不在这里显示，在工作台的“实体”面板看。

### 9.6 为桌面端留的位置

现在的外壳是浏览器里的工作台，面板放在底部抽屉里。以后做桌面端时：

- **同一份面板放进窗口**，成为顶部“案件 / Agent / 记录”里的两页。面板只通过本机服务的接口读写（`/api/hosts…`），不直接碰文件，换外壳不用改。
- **网关不随窗口关闭而停**。关窗口是收到托盘，网关继续运行。
- **托盘图标**带状态圆点，点开是精简面板：网关状态一行、各 Agent 的开关、“打开 Mask”“退出”。
- **退出时还有 Agent 接入**，询问：断开并退出（主按钮）/ 只退出（Agent 发不出请求，直到 Mask 再次启动）/ 取消。借鉴 `internal/gui/quitask.go`。
- 登录自启由桌面端负责（第 10 节第 3 项）。
- 黑色灵动岛只给核对工具用；窗口顶部的页面切换用浅色分段控件。

接口（工作台和以后的桌面端共用）：

| 接口 | 作用 |
| --- | --- |
| `GET /api/hosts` | 网关状态、今天的计数、每个 Agent 的状态和详情 |
| `PUT /api/hosts/{id}` | 接入或断开 |
| `GET /api/hosts/{id}/preview?enabled=` | 将要改的文件和行差异 |
| `POST /api/gateway/start` | 启动网关 |
| `GET /api/gateway/log?day=` | 记录 |

## 10. 待定

1. **读不出工作目录的请求。** Agent 会发不带环境信息的小请求（如给会话起标题），里面可能有用户输入的文字。建议：用全部项目的映射库改写，同一原文在多个项目里时取最近修改的那个项目的代号。这类请求的回复不需要还原。它们是否带工作目录，第 11 节第 1 步抓真实请求时确认。
2. **案件文件夹路径含真名。** 第一版拒绝并说明。其他做法：
   - 按项目明确开启“路径照发”：工作目录这一个字符串不改写，文件夹名会发给厂商。
   - 只在回复的工具调用参数里把带代号的路径换回真实路径：要解析流式回复，一段路径可能被切在两个事件之间，需移植 `internal/redact/writer.go` 的扣尾逻辑。
   - 用户把文件夹改成不含真名的名字。项目按路径哈希绑定，改名后是新的空项目（[文件管理与 AI 隔离方案](文件管理与AI隔离方案.md) 问题 6），要先解决这一点。
3. **随登录启动。** 建议接入第一个 Agent 时写 `HKCU\…\Run`，断开最后一个时删除。magpie 在 Windows 上也只有登录自启（`internal/autostart/autostart_windows.go`）。
4. **Codex 和 DeepSeek Harness 第一版不接。**
