# 架构与模式

日期：2026-11-09。描述当前代码。

## 分层

```
mask/
├─ categories.py   类别目录（读《规则.md》的结构块）+ 固定形状号码的规则与校验位
├─ detect.py       把识别结果定位成候选：模型值、简称定义、规则补充
├─ vault.py        映射库：主体、代号、还原、已知原文替换
├─ store.py        本机加密读写（Windows DPAPI）
├─ documents.py    TXT / DOCX / PDF 读取与原位置导出
├─ official.py     官方 has-anonymizer 1.0.3 与 llama.cpp 的适配
├─ project.py      项目：材料、候选、核对、导出、交接、状态
├─ __main__.py     命令入口，按模式分发
└─ modes/
   ├─ workbench.py 工作台模式：本机浏览器应用
   ├─ skill.py     Skill 模式：宿主技能调用的命令
   ├─ guard.py     拦截模式：宿主 hook 与本地代理
   └─ install.py   把技能和拦截装入宿主（目前只有 DeepSeek Harness）
```

`modes/` 之外的模块不知道自己被哪个模式调用。三个模式都只通过 `Project` 和 `Vault` 读写状态，不各自保存副本。新增一种模式是在 `modes/` 加一个文件，并在 `__main__.py` 加一条子命令。

## 三种模式

| 模式 | 命令 | 材料怎么进来 | 结果怎么出去 |
| --- | --- | --- | --- |
| 工作台 | `python -m mask` | 用户在浏览器选文件 | 下载脱敏稿，本机还原 |
| Skill | `python -m mask skill start` / `status` | 宿主技能打开同一个工作台 | 用户点“交给 AI”，脱敏稿写入工作目录的 `mask-handoff/`，宿主读取 |
| 拦截 | `python -m mask guard hook` / `proxy` | 宿主发往模型的内容 | hook 拦下含真名的输入；代理把已知原文改成代号后转发 |

### 工作台

与此前相同的界面和流程。`--host` 表示由宿主技能发起：主按钮从“导出脱敏稿”变为“交给 AI”，导出 Markdown 时同时写入 `<工作目录>/mask-handoff/`。

### Skill

技能文件在 `integrations/skill/mask/SKILL.md`，装入宿主的技能目录即可；它只运行两条命令。

- `skill start`：项目的工作台没在运行就启动一个（后台进程），在运行就让它重新打开浏览器。一次性启动链接由工作台直接交给浏览器，不出现在命令输出里。
- `skill status [--wait 秒]`：输出材料数、待识别数、待确认数、是否已交接、脱敏稿路径。输出会进入宿主对话，因此不含文件名、原文和代号对应关系。

没有使用 MCP：三个宿主的技能都能运行命令，命令行是它们的共同部分。

### 拦截

两个拦截点共用 `guard.scrub`：把映射库里已确认的原文替换成代号，并找出校验位有效但未脱敏的身份证号、统一社会信用代码。拦截不运行识别模型，因为那里的判断没有人核对。

- **hook**（`guard hook`）：从标准输入读宿主的 hook 事件。`UserPromptSubmit` 里出现已脱敏的真名时拒绝发送，并告诉用户对应的代号；`PreToolUse` 读取已导入的原件或 Mask 项目数据时拒绝。hook 只能拦，不能改写。检查本身出错时以退出码 2 拒绝。配置示例见 `integrations/guard/claude-code.settings.example.json`。
- **代理**（`guard proxy --upstream <模型服务地址>`）：宿主把模型地址指向 `http://127.0.0.1:8788`。代理改写请求体里的每个字符串后转发，回复原样流式传回。请求体不是 JSON、或含未脱敏的强校验号码时返回 400，不转发。模型回复不做还原：真名只在工作台还原，不进入宿主对话和它的本地会话记录。

代理是唯一能同时覆盖“对话里打的字、`@` 引用、工具读到的文件内容、上下文压缩”的位置。

## 识别

1. 按类别组分次请求 HaS（主体、联系方式、证件、账户与编号，以及用户开启的按需组）。一次请求带全部类别时，样例起诉状漏掉了合同编号；分组后不漏，总耗时相近（1.2 秒对 1.3 秒）。
2. 程序补充：`（以下简称“X”）` 的简称；身份证、统一社会信用代码、银行账号（校验位），手机号、邮箱、IP、车牌、案号（形状）。只在模型没有给出重叠候选时补充。
3. 规则提示：角色词、占位符、法院和政府机关标为保留；夹带角色或后续字段的候选给出提示。

所有候选都要用户决定。重新识别（失败重试、改了脱敏范围、旧项目升级）保留相同位置上已做的决定和手工补录。

## 映射库

一个项目一个映射库，结构只有四项：

| 项 | 含义 |
| --- | --- |
| `mapping` | `{代号: 原文}`。一个代号对应一种原文写法 |
| `entities` | 主体：类别、编号、它的各种写法。同一主体的写法共用编号，代号后缀为 `名称`、`名称2`… |
| `issued` | 已经随导出离开工作台的代号。不释放、不改派 |
| `reserved` | 原文里本来就有的代号形状文字。不分配 |

规则：

- 代号只在用户决定“遮住”时分配；改回“保留”且从未导出过的代号立即释放。
- 还原单遍替换，还原出的文字不再被扫描。映射里没有的代号列为缺失；形状被 AI 改动的代号只给建议，不自动替换。
- 导出的 `mapping.json` 是官方 `{代号: [原文]}` 结构，只在用户主动导出时生成。

存放与保护：

- `%LOCALAPPDATA%\Mask\projects\<工作目录哈希>\vault.mask` 是映射库，`project.mask` 是材料文字与核对状态。两个文件用 Windows DPAPI 按当前 Windows 账户加密：其他账户、拷到别的电脑的副本打不开。以同一账户运行的程序仍能解密，这不是对本机 AI 工具的隔离；硬隔离见 [文件管理与 AI 隔离方案](文件管理与AI隔离方案.md)。
- `%LOCALAPPDATA%\Mask\default-scope.json` 是用户保存的新项目默认脱敏范围，只有类别名，不加密。读取时忽略《规则.md》里已不存在的类别；没有保存过时新项目取标准类别。旧项目迁移不使用它。
- 映射不写入工作目录，不进入 `mask-handoff/`、下载的脱敏稿和 ZIP，不出现在 `skill status` 的输出里。
- 导入时的原件快照、生成的脱敏稿和还原后的真名版仍是普通文件，位于同一项目目录。
- 旧版的明文 `project.json` 在首次打开时转换为上述两个文件，校验一致后删除。
