# Mask 交互原型

双击 `mask.html` 即可打开，无需安装依赖。这个目录只有模拟的部分：`sim.js` 是示例合同、模拟的宿主对话、场景和“原型”面板，`sim.css` 是它们的样式；界面本身用的是产品的 [mask/web/app.js](../mask/web/app.js) 和 [app.css](../mask/web/app.css)，所以要和 `mask/` 目录放在一起才能打开。用 HTTP 服务打开时从仓库根目录起服务，访问 `/prototype/mask.html`。`mask-workflow.html` 是上一版，保留作对照。

真实文件模式请在项目根目录运行 `python -m mask`，由本地服务加载 `mask/web/` 下的页面。它和本文用同一份核对界面，使用真实读取、HaS 识别、持久化、导出和还原；不显示模拟宿主对话。操作方式与已支持的文档结构见 [项目 README](../README.md)。下文的“原型范围”和历史浏览器核对记录仅指直接打开 HTML 的模拟模式。

`mask-gateway.html` 是“接入 Agent”面板的原型，对应 [网关方案](../docs/网关方案.md) 第 9 节：每个 Agent 一个开关、断开并还原、记录，以及桌面端外壳下同一份面板和托盘的样子。左下角“原型”切换外壳（工作台 / 桌面端）和场景（第一次、已接入、被别的工具改掉、网关停了），并可模拟 Agent 那边发来请求。数据是示例，不改任何文件。

## 用户交互流程分析

用户的核心任务只有一个判断：**这个词能不能让 AI 看到。** 其余步骤都服务于这个判断，或者可以由系统带着走。

| 阶段 | 用户实际要做的 | 频率 | 设计处理 |
| --- | --- | --- | --- |
| 发起 | 在宿主说一句需求 | 每次 1 次 | 不属于工作台。需求原话成为工作台首页的标题 |
| 选材料 | 默认全选，偶尔取消或添加 | 每次 1 次 | 文件清单，一行一份，点行切换勾选；已识别的行显示待确认数，点它回到核对；下方一个与清单同宽的“开始识别”按钮，文件多时停在底部 |
| 识别 | 等待 | 自动 | 不放进度条，原文由淡转实，墨块逐段出现 |
| 逐处确认 | 看一处，决定遮或留 | **高频** | 自动跳到下一处；宽屏时决定卡片停在文档右侧空白处、与该词同高，用细线连回该词，窄屏时在该词上方或下方 |
| 修正类别、范围、主体 | 偶尔 | 低频 | 收进弹层；范围改为拖手柄 |
| 查漏 | 搜索、划选 | 中频 | 顶部灵动岛里查找，黄色高亮结果；划选后出现遮住按钮 |
| 交接 | 看汇总，确认一次 | 每批 1 次 | 底部抽屉，只列数量、例外和去向 |
| 回对话 | 发送“继续” | 每批 1 次 | 一个按钮，宿主支持时无需操作 |
| 还原 | 粘贴结果，处理缺项 | 每批 1 次 | 与核对相同的语法：朱色待处理，清零后保存 |

核对页的全部工具集中在顶部的灵动岛：`原文 / 脱敏后` 切换、查找、`标注`（涂黑笔、橡皮、框选，打开后在灵动岛下方展开一条工具栏）、`实体` 面板、`⋯` 菜单（导出原格式、添加材料、稍后继续）和主按钮，按钮都带文字。窄屏只保留图标。灵动岛是浅色毛玻璃：黑色只用于“遮住”。

左侧悬浮的“待处理”看板把主按钮背后的清单摊开：一行一处待确认、重叠范围或识别失败，点行跳到原文；处理完一行就消失。看板顶部的“全部候选”切换为每一处候选的清单，可从这里选中被盖住的重叠候选；没有待处理时只剩这一页。行下的小字只在特殊情况出现：`在「全称」里`（嵌套在长候选内，通常保留）、`= 全称`（可并入的简称）、范围过宽或重叠。看板顶部的“待确认 / 遮住 / 保留”样块同时是图例和计数。看板按文件分组，文件行带缩略图和待确认数，点它切换材料；看板展开时不再单独显示缩略图栏，收起后缩略图栏回到看板下方。待处理清单末尾是“其余 N 处全部遮住”。宽屏默认展开，1060px 以下默认收起，点行后自动收起。

## 交互语法

全部页面只用这几条规则，学会一处就会全部：

1. **黑条加锁 = 遮住，AI 看不到。** 实物涂黑的直接转译；切到“脱敏后”时黑条里显示 AI 收到的代号。
2. **朱色虚线框 = 待确认，需要你决定。** 朱色取自朱批和印泥，只用于待办；处理完后它移到主按钮上。
   **浅绿底加绿线 = 保留，AI 能看到原文。** 查找结果用黄色荧光笔，与三种标注都不重叠。
3. **👁 保留 / 👁̸ 遮住 决定一处。** 图标旁附两个字，所有弹层相同。
4. **一个主按钮。** 在灵动岛最右侧，写明下一步：有待办时显示“N 处待确认 ›”，点它去下一处；清零后变成发送。按钮不会出现“灰着点不了”的死状态。
5. **箭头表示数据去向。** → 留在本机，↑ 发给 AI，↓ 存到本地。

参考来源：底部输入框从居中落到底部、衬线正文、工具调用折叠来自 Claude；浮动工具、毛玻璃材质、划选弹出菜单、拖动手柄、底部抽屉、角标、圆环、弹性动画和深色模式来自 Apple HIG。

## 完整体验

左下角“原型”可切换宿主和场景，这个控件和虚线按钮都不属于产品。Codex 用 `$mask`，Claude Code 和 WorkBuddy 用 `/mask`；`@mask` 不作为入口。

1. 点击发送。工作台约 1 秒后升起，预列当前工作目录的文档。
2. 点击 →。文件逐份识别，已完成的可先核对。
3. 在“查找”输入“张三”，点 👁̸ 补录；在原文中划选 `XH-2026-018`，点 👁̸ 补录。
4. 点灵动岛右侧的“处待确认”，逐处处理：“联系人”点 👁 保留；“海岚”点“= 海岚咨询有限公司”；“海岚咨询有限公司（盖”先把右侧手柄拖到“司”后，再点 👁̸。
5. 按钮变成朱色 ↑，点击后查看汇总并确认交接。
6. Codex、WorkBuddy：点“回到 Codex，发送‘继续’”后发送。Claude Code：自动继续。
7. 点虚线按钮“请求还原”并发送。点朱色的 `<公司[9].公司.名称>`，选一个已有代号或保留代号，再点 ↓ 保存。

值得单独试的分支：

- 虚线按钮“用 @ 引用原件”：消息被拦截，不发给模型。
- 交接后在对话里写真名：被拦截，并给出代号写法。
- 交接前发送“继续”：回复材料尚未交接和待确认数量。
- `⋯` → 稍后继续：回到对话，之后发送 `$mask 继续核对` 恢复。
- `⋯` → 导出原格式：与交给 AI 的 Markdown 相互独立。
- 灵动岛“脱敏后”：切到 AI 看到的内容，真名变代号，文件名变“材料 N”。
- 灵动岛“实体”：实体与代号面板，每行的眼睛按主体批量处理。
- 灵动岛“标注”：B 涂黑笔划过“100,000”立即遮住，E 橡皮点它撤回补录，R 框选“签约主体”整段改为保留，Ctrl+Z 逐步撤销。
- 看板“全部遮住”或 `⋯` → 全部遮住待确认：一次处理全部待确认，范围过宽的“海岚咨询有限公司（盖”会留下。
- 弹层里的 ⧉ 数字：把当前决定同步到相同内容的全部位置，必须手动触发。

## 原型范围

- 不连接 HaS、云端模型或真实 Codex / Claude Code / WorkBuddy 插件；分析回复为固定示例。
- 对话区只模拟文字、表格和链接。虚线按钮只负责填入示例文字，真实宿主没有。
- 本地文件选择和拖放只使用文件名；不读取文件内容，不上传文件。预览始终是内置合同示例，并在页面标明。
- 所有状态只存于当前页面内存，刷新重置；识别和安装进度是示例，未实测。
- 未实现真实文档解析、脱敏文件导出、真实交接和文件保存。工作目录文件列表、`mask-handoff/`、`mask-export/`、`mask-restored/` 都是示例路径。
- 页面用系统字体，文档正文优先 Noto Serif SC。未安装时回退到宋体，观感会变。

## 依据与待验证

三端行为按官方文档、本机 Codex 0.164.0 和本机 WorkBuddy 插件目录设计，未在宿主里实际调用：

- Claude Code 自动继续依赖 MCP 调用转后台；长时间核对是否受 30 分钟空闲窗口影响待测。
- Codex 的 MCP 工具默认 60 秒超时，所以默认走“发送继续”。`codex queue` 能否实现自动续接待测。
- WorkBuddy 的 `/mask` 调用来自第三方教程，回传机制未见官方说明。
- 拦截 `@` 原件和真名依赖 `UserPromptSubmit` hook。Hook 只是护栏，能拦截但不能改写；Claude Code 文档未说明它与 `@` 展开的先后顺序，Codex 插件 hook 需要用户信任后才运行。

设计上待验证：没有文字说明时，法律工作者能否靠图标理解 👁 / 👁̸ 和拖动手柄。原型未做用户测试。
